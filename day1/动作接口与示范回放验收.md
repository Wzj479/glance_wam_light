## 1. 坐标系、缩放和旋转到底是什么

实际控制链路：

```text
检查点域的归一化动作 z
    ↓ 官方反归一化（夹爪不做 min/max 仿射变换）
机器人控制命令 u=[x,y,z,rx,ry,rz,open_gripper]
    ↓ 夹爪 0/1 转环境 +1/-1
LIBERO OSC_POSE
    ↓ 截断与控制器缩放
目标位姿增量 δp=0.05*u[:3]，δr=0.5*u[3:6]
    ↓ OSC 跟踪与 MuJoCo 动力学
实际末端位姿、夹爪和物体运动
```

这里的 x/y/z 是 MuJoCo 固定世界坐标系的轴，不是主相机坐标系，也不是随夹爪转动的工具轴。`ctrl.ee_pos` 使用末端 site 的世界位置；`set_goal_position()` 直接计算 `current_position + delta`。

旋转使用旋转向量，也就是“旋转轴 × 旋转角”：

```python
R_goal = Exp(delta_rotation_vector) @ R_current
```

左乘表示世界轴增量。右乘 `R_current @ Exp(delta)` 是工具轴增量，这里不适用；也不能把三维命令依次解释为欧拉角 xyz 旋转。

在实际非单位初始姿态下，混合旋转命令的目标矩阵比较：

- 世界轴左乘最大矩阵元素误差：`2.0633e-8`。
- 误用工具轴右乘：误差 `0.17734`。
- 误用 xyz 欧拉角：误差 `0.0033832`。

四元数记录顺序是 **xyzw**。视频图像旋转 180° 是为了和训练图像方向一致，不改变动作坐标系，不对动作分量做图像旋转。

输入 `u_x=0.1` 设置向世界 +x 偏移 **5mm 的目标**；`u_rx=0.1` 设置世界 x 轴 **0.05rad 的目标旋转**。它们不是保证每步实际移动的距离或速度。实际响应包含控制跟踪滞后、惯性和接触影响。曲线中的灰色区间为持续 8 个控制周期的脉冲；方向检查扣除了同初始状态零输入轨迹的漂移。

±2 只用于 `controller.set_goal()` 的裁剪数值检查，没有把越界指令施加给机械臂环境。环境接口仍使用 [-1,1] 范围。

## 2. 本次查出并修正的归一化错误

单独 goal 数据集的已发布统计，与已发布机器人检查点使用的合并统计，在第六维不同：

```text
goal stats_gr00t.json：yaw.min = -0.2871428430080414
checkpoint franka：   yaw.min = -0.3675000071525574
```

之前的正式微调代码直接构建 SingleDataset，会默认使用单数据集边界；保存和推理却沿用检查点边界，形成训练/部署尺度不一致。这是此前接入遗漏的实际问题。

用这次真实 112 步动作验证：

- 未对齐时，第六维控制命令最大往返误差 **0.06751**。
- 本应为零的第六维命令，会恢复成约 **-0.04551**，对应控制器目标偏差约 **-0.02276rad**。
- 对齐后包含 float16 量化的第一至六维最大命令误差为 **2.2757e-4**。
- 对应最大平移目标量化误差约 **0.0114mm**，最大旋转目标量化误差约 **2.28e-5rad**。
- 112 行夹爪环境命令全部与原始示范一致。

修正方式：新增 `finetune_utils.checkpoint_action_metadata()`，在 `build_splits(cfg,a,stats)` 构建每个官方 SingleDataset 后，将检查点 `stats['franka']['action']` 的 min/max 写入复制的 transform metadata，再调用官方 `set_transforms_metadata()`。这发生在样本打包成 float16 之前，没有先把错误的 float16 标签再做逆变换。

原始 dataset metadata 不被就地改写；轨迹划分、图像、原始物理动作不变。要求 mask 是 `[true,true,true,true,true,true,false]`，避免错误地归一化夹爪。训练清单记录实际使用的 min/max/mask，导出模型继续保存同一份检查点统计。

`check_action_roundtrip_cpu.py` 通过 AST 提取固定版本官方 `ModelClient.unnormalize_actions()` 和 `_binarize_gripper_open()` 的真实函数，执行其 NumPy 后处理，不导入模型依赖。此次测试使用真实检查点旁的 `dataset_statistics.json`，不是自行假设范围。检查点权重本身没有下载或加载。

正式 GPU loader/梯度更新仍待后续运行；这里已通过数值往返检查、metadata 覆盖辅助函数测试。先前两个数据审计目录中的 NPZ 保留了当时的单 suite 归一化，不能直接拿来正式微调。

## 3. 初始状态如何匹配，为什么可以确认

没有假定 `episode 0 == demo_0`，也没有把评测用的第 0 个随机初始状态当作训练示范初始状态。

实际过程：

1. 读取 LeRobot episode 0 的完整 112×7 动作。
2. 只转换夹爪编码：0→+1、1→-1；其余六维保持原始控制命令。
3. 对原始 HDF5 的 50 条轨迹逐条比较完整动作序列，同时考虑官方 no-op 过滤规则。
4. 唯一匹配 `demo_10`；该条过滤前后均是 112 步，没有删除 no-op。
5. 提取该条 `states[0]` 的完整 79 维状态，以及 XML 中关节顺序；服务器验证顺序和状态维数，再恢复状态。
6. 按 OpenVLA 再生成示范的协议执行 10 步零位姿命令、夹爪打开的稳定等待，然后回放动作。

初始状态不只是机器人关节，也包含可动对象、关节速度和仿真时间。恢复后全状态最大差为 0，源模型与当前场景的全部关节名称和顺序相同。随后回放的末端轨迹几乎精确重现 LeRobot proprio 记录，为匹配提供了第二层验证。

原始来源：

```text
HF: yifengzhu-hf/LIBERO-datasets
revision: f13aa24a3da8c43c7225569f28c562979fa0e35a
path: libero_goal/put_the_bowl_on_the_plate_demo.hdf5
published LFS SHA256:
e69528b0cf10dfc59b20698e12ec2affc03f3887309034d3eb74cac3ec929406
```

匹配脚本通过 HTTP Range 读取 HDF5 的元数据、动作和状态，未把 468MB 的原始图像文件传到服务器；记录了固定 revision、预期 LFS SHA 和提取 NPZ 的实际 SHA。`match.json` 明确注明 Range 匹配阶段未重新计算整个源文件哈希，不把预期 SHA 冒充实测 SHA。

LeRobot 版本仍为 `0b9208dff852914f94be879f702cd40118255bce`。GlanceWAM 代码版本仍为 `6a51bdc5139e72e8ad525779db0c989e1af5abab`。

## 4. 对照结果

| 协议 | 放置成功 | 对示范位置 RMSE | 对示范旋转 RMSE |
| --- | --- | ---: | ---: |
| 匹配状态 + 等待 10 步 | 是 | 2.9548e-8m | 7.3029e-8rad |
| 匹配状态 + 不等待 | 是 | 1.0356mm | 0.04147rad |
| 等待 10 步，完全重复 | 是 | 同第一行 | 同第一行 |

不等待时，初始观测与示范的末端位置相差约 4.80mm；这条任务仍能成功，但已经不能精确复现示范记录。因此“回放最后成功”不能代替初始化与时序检查。

两次标准回放的完整仿真状态最大差为 0。第一次在动作索引 92 后满足成功谓词，即执行第 93 条动作后；这里只报告同一条记录示范的诊断，不把重复执行当作多个独立评测回合。

## 6. 复跑

在已有项目和已提取输入数据上，按顺序运行，防止两个渲染进程同时挤占 2GiB：

```bash
cd /root/autodl-tmp/wam_glance_project
bash day1/run_action_acceptance_cpu.sh
```

脚本不会加载模型或安装包，会重写本任务的同名输出文件。原始数据和原始资产目录保留。

重新匹配源数据时，在可访问 Hugging Face 的主机执行：

```bash
python day1/match_grasp_source.py \
  --data-root /absolute/path/to/libero_goal_no_noops_1.0.0_lerobot \
  --out /absolute/path/to/matched_grasp_source --episode 0
```

该匹配脚本使用 h5py、fsspec、PyArrow、NumPy；服务器运行回放只需已提取 NPZ，不需要 h5py，不读取任意 pickle。服务器当前匹配输入为 `data/matched_grasp_source`。

完整结果为 `wam_action_acceptance_full.zip`，包含原始曲线、视频、CSV、数值轨迹与源状态片段。`wam_action_acceptance_review.zip` 是较小的报告/曲线/视频审阅包，包含逐文件 SHA256。代码修正包含在 `wam_action_acceptance_scripts.zip`。

## 7. 对后续微调的意义

现在已实际确认：示范中的控制命令、夹爪编码、仿真状态和 20Hz 时序可以接上现有控制器；正式训练的标签尺度也已统一到检查点域。

恢复 A100 后：下载完整视频和模型，复用显式 episode 清单，先做 10 步动作模块微调；验证官方完整 loader 输出、冻结特征一致性、参数更新和导出重载，再让模型自己产生动作做闭环评测。当前记录动作回放成功不能证明模型已经学会抓取。
