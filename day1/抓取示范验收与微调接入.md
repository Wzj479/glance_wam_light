## 夹爪标签和控制命令必须分清

官方训练数据与模型输出的第 7 维：**1=打开，0=闭合**。保持原值进入训练，不能先转换成 -1/+1 再微调。

官方评测端在送入 LIBERO 前执行：

```python
libero_gripper = 1.0 - 2.0 * (predicted_open > 0.5)
# 模型 open=1 → 环境命令 -1：打开
# 模型 open=0 → 环境命令 +1：闭合
```

这说明上次抽屉任务的常量 `+1` 是训练数据的“打开标签”，不是闭合控制命令。开合是动作标签，不能仅由标签推断物体已被实际抓牢；本次没有做物理回放成功率验证。

## 切换样本怎样读取

训练轨迹 0 长 112 帧，夹爪在局部第 48 帧变为闭合，第 99 帧变为打开：

```text
闭合窗口 t=45：动作帧 45…52
gripper = [1,1,1,0,0,0,0,0]

释放窗口 t=96：动作帧 96…103
gripper = [0,0,0,1,1,1,1,1]
```

验证轨迹 52 的对应窗口为 `t=38` 和 `t=89`，同样保留真实切换标签。另有 `t=109` 的尾部补齐窗口。

每个起点 t 的样本契约仍是：

```text
image[0] = 观测 t，双相机拼接
image[1] = 未来监督 min(t+48,末帧)
image[2] = hindsight 目标 min(t+g,末帧)，g∈[1,48]
action   = t…t+7，越界按官方元信息重复最后动作
language = put the bowl on the plate
goal_offset_rows = 请求的 g
```

图像数组 `[3,224,448,3]`，动作 `[8,7]` float16。前三张图像按角色排列，不按时间升序。第 1～6 维沿用已发布的 min/max，第 7 维保持 0/1；未重新拟合子集归一化参数。

修正：本次审计 NPZ 的 min/max 来自单个 goal 数据集，不等于正式检查点的合并统计。后续接口验收确认 yaw.min 分别为 -0.287142843 和 -0.367500007。正式训练已在 `build_splits()` 中调用 `checkpoint_action_metadata()`，使用检查点的 franka 边界重设官方 transforms，再生成动作标签。原始物理动作、轨迹名单和抓取开合统计不变；不要拿审计 NPZ 直接代替正式 loader。

输出 `sample_windows.png` 的五行依次为：训练闭合、训练释放、验证闭合、验证释放、训练尾部。每行三列为当前、未来、目标，每个小图左主相机、右腕部相机。

暗光/颜色变化在整窗口中使用相同参数；保存的动作、语言和目标偏移保持一致。生成的 NPZ 是审计样本，不是后续训练数据集。

## 后续接入正式动作模块微调

### 1. 使用完整原始数据，不训练审计 PNG / NPZ

GPU 环境准备好 GlanceWAM 代码、依赖、官方机器人检查点、SkyReels 基座和足够磁盘后，在 GlanceWAM 仓库根目录下载固定版本整个 goal 数据目录：

```bash
hf download LinhanWang/GlanceWAM --repo-type dataset \
  --revision 0b9208dff852914f94be879f702cd40118255bce \
  --local-dir glancewam_bundle \
  --include 'datasets/libero_goal_no_noops_1.0.0_lerobot/*'
```

保留原始目录名，`DATA_ROOT` 必须指向其父目录 `glancewam_bundle/datasets`。这同时获取视频、Parquet、元数据和官方 T5 缓存。训练脚本使用缓存文本特征，缺失缓存会报错；当前 CPU 缓存不能替代它们。当前服务器剩余空间约 2.9GiB，未在其上下载模型。

把本次更新的 `day1` 文件放到 GPU 上的 GlanceWAM 仓库 `day1` 下。特别需要同步 `finetune_action_head.py`、`finetune_utils.py`、`run_finetune_a100_40g.sh` 和依赖的原有 smoke 等脚本，不要只复制启动文件。

### 2. 直接沿用验收轨迹，不重新随机划分

新增参数：`--episode-split PATH`；启动脚本通过 `EPISODE_SPLIT` 传入。两个可选清单：

- `grasp_episode_split.json`：只训练本次抓取任务，8 / 2 条；建议先用它跑 10 步。
- `drawer_grasp_episode_split.json`：抽屉和抓取一起训练，16 / 4 条。

`build_splits()` 从官方 loader 的 `all_steps` 中筛选指定 episode。没有列出的其他任务不会进入训练或验证。遇到重复 ID、训练验证重叠、ID 不存在、空集合或 dataset 名不匹配，会直接报错。输入清单 SHA256 写入训练输出。

`--val-fraction` 在显式清单模式下不参与重分配。验证仍按 `--val-stride 8` 取起点，再固定抽至 `--val-samples`；因此验证损失窗口数不等于原始验证数据行数。可视化的目标抽样使用 epoch=0，训练脚本固定验证使用 epoch=-1；验证目标也是可重复的，但不保证和审计图相同。

服务器已用真实 Parquet 和训练脚本共用的筛选函数验证：抓取清单得到 766 个训练窗口、26 个 stride=8 验证窗口；合并清单得到 1,849 个训练窗口、61 个 stride=8 验证窗口。`grasp_split_check.json` 和 `drawer_grasp_split_check.json` 保存实测结果。这项检查没有加载完整官方 loader。轨迹筛选、隔离和其他已有 CPU 单元测试本地共 22 项通过，其中筛选/增强/检查点辅助函数相关 13 项也在服务器通过。

### 3. 冻结与损失

当前 `--train-scope all` 表示**动作模块全部可用参数**，不是全模型微调：

```python
model.requires_grad_(False)
model.action_model.requires_grad_(True)
# 无状态 LIBERO 路径不使用 state_encoder，将它继续冻结。
```

世界模型、VAE 和其他非动作模块冻结；特征提取处 `no_grad` 且条件特征 detach。只有 `action_model.*` 进入优化器。验证冻结哈希、动作模块更新和检查点重载仍需在 GPU 实际执行。

归一化统一使用加载的检查点 `stats['franka']['action']`；不是只保存该文件就完成对齐。代码已将 min/max 显式写入 loader 的 transform metadata，第 7 维要求 mask=false。接口验收在服务器用真实 112 步动作和官方 NumPy 后处理验证了 float16 往返误差；完整 GPU loader 集成仍待验证。

7 维动作，包括夹爪，共同使用官方 Flow Matching 损失：

```python
epsilon = randn_like(action)
x_t = (1-t) * epsilon + t * action
target_velocity = action - epsilon
loss = mean((action_head(x_t, t, frozen_features) - target_velocity)**2)
```

若配置启用 `t_loss_weighting`，遵循官方时间权重。没有另加夹爪 BCE 分类损失，也没有在训练前将夹爪阈值化为 -1/+1。在线控制时才按官方接口阈值映射。

### 4. 单张 A100 40GB 的下一次验证命令

以下命令需在**已准备好的 GPU GlanceWAM 仓库根目录**运行，当前 CPU 服务器未执行。`CKPT`、`BASE_MODEL`、`WAM_PYTHON` 沿用主实施方案中已准备的路径；跨服务器时先复制 split 清单，修改 `AUDIT_ROOT`。

```bash
AUDIT_ROOT=/root/autodl-tmp/wam_glance_project
EPISODE_SPLIT="$AUDIT_ROOT/results/grasp_episode_split.json" \
DATA_ROOT="$PWD/glancewam_bundle/datasets" DATA_MIX=libero_goal \
MAX_STEPS=10 WARMUP_STEPS=1 GRAD_ACCUM=1 EVAL_EVERY=10 SAVE_EVERY=10 \
VAL_SAMPLES=8 AUG_PROB=0 SEED=42 TRAIN_SCOPE=all \
OUT_DIR=results/finetune/grasp_clean_10steps \
bash day1/run_finetune_a100_40g.sh
```

先确认显存、官方特征对齐检查、冻结哈希和梯度检查、模型重载全部通过，再增加步数并做干净/增强对照。增强组设置 `AUG_PROB=0.5`，其余数据清单、种子和训练步数保持一致，使用新输出目录。10 步只是集成验收，不能证明控制能力提升。

合并两任务时，打开标签占 1,853/2,321，约 80%；只看整体动作损失容易掩盖闭合事件。先在单抓取任务上确认能学习切换，再做二任务控制对照。报告按任务、夹爪打开/闭合和切换附近窗口分别检查；最终用抓取放置闭环成功率和失败视频判断，不能用离线 Flow Matching 损失代替成功率。

当前只完成 CPU 数据审计、显式清单接入代码与 CPU 检查，未实测 A100 显存、完整 loader 或模型训练。预训练可能见过这些示范，本次划分是适配 holdout，不是未见任务泛化。
