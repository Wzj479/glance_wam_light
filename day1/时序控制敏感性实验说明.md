# 单条抓取示范的时序控制敏感性实验

## 实验范围

2026-10-16，复用现有 2GiB CPU 容器、LIBERO CPU texture1024 诊断资产，以及已匹配的 LeRobot episode 0 / 原始 HDF5 demo_10。不是世界模型推理、VLA 推理或后训练实验。

研究问题：同一条记录动作在起始等待、夹爪错时和动作命令保持时，放置任务与物体运动如何变化。

实测九个条件最终均放置成功。基准最大抬升 125.851mm；夹爪延迟 50/100/200ms 时分别为 124.263/123.044/113.429mm；命令刷新 10/5Hz 的保持组分别为 126.082/124.829mm。200ms 夹爪错时对应约 12.42mm（9.9%）的抬升下降，但没有使这条示范放置失败。这不是“最大可容忍 200ms”的结论，也不是模型闭环延迟鲁棒性证据。

原示范 112 步；固定 20Hz 控制调用、seed=42、同一个完整初始状态，以及正式记录前的 10 步稳定等待。所有条件统一执行 **136 步 / 6.8 秒**，不把延迟后未执行完的动作截掉。

上述频率、延迟和时长均使用仿真时间；CPU 实际运行慢于实时，视频按仿真时间以 20fps 播放。没有测量模型推理耗时、真实系统截止期或硬件实时控制能力。

## 九个预定条件

| 条件 | 具体操作 |
| --- | --- |
| baseline | 执行 112 个原始动作，再执行 24 步零位姿、夹爪保持最终状态 |
| all_delay_1/2/4 | 原始七维动作整体延后 1/2/4 步，即 50/100/200ms；开头使用零位姿、夹爪打开，动作完整执行后补等待 |
| gripper_delay_1/2/4 | 前六维保持原时序，只把夹爪命令延后 1/2/4 步，末尾冲刷完成 |
| hold_2 | 每两步才更新七维动作值，中间重复上一条命令，命令刷新 10Hz |
| hold_4 | 每四步更新七维动作值，中间重复上一条命令，命令刷新 5Hz |

`control_hz` 始终为 20。保持组改变的是 `command_refresh_hz`；MuJoCo 内部积分和 OSC 控制调用不变。

必须区分三个概念：

- **整体延迟**：这里是固定动作流的起始时移，不包含模型读到旧观测、重新决策或动态障碍物；不能据此评估真实闭环 sensor-to-action 延迟。
- **命令保持**：重复同一个增量命令，控制器每个周期仍按当前位置计算新目标；不是保持同一个绝对位姿。
- **WAM 动作块**：包含多个不同的未来动作，可在低频推理后按 20Hz 逐步消费；不是把一个动作重复多次。

例如原始夹爪在第 48 帧闭合、第 99 帧释放。夹爪延迟四步会把它们改为第 52 和 103 帧，但机械臂位置命令不跟着延后。因此只有这一组直接破坏机械臂与夹爪的相对时序。

## 输出与判定

每个条件保存实际执行的动作、完整仿真状态、末端位置和姿态、夹爪关节位置、碗和盘的世界位置，以及每步任务谓词。

主要量：

- 最终任务成功：使用 LIBERO 任务自身的成功谓词，不用抬升阈值代替。
- 最大碗抬升：相对该条件初始碗高度，单位 m / 图表 mm。
- 最终碗盘 XY 距离：物体根部位置的平面距离，不是任务成功判定的充分条件。
- 首次成功动作索引：JSON 中从 0 开始；也保留 `ever_success`，避免掩盖后来失败。
- 控制时间轴上的实际夹爪宽度、末端轨迹和物体运动。

全部条件必须满足相同的初始状态 SHA256 和控制步数。基准若失败则拒绝接受整组实验。每个条件只有一条示范，不把不同条件视作多个独立初始状态，也不报告总体成功率或统计显著性。

## 结果入口

实际结果由服务器运行后生成，见 `results/control_sensitivity/analysis.md` 和 `summary.csv`，不以预计结果代替实测。

| 文件 | 用途 |
| --- | --- |
| `summary.json` / `summary.csv` | 九个条件的结果、时序参数和峰值内存 |
| `analysis.md` | 实测结果表和实验边界 |
| `sensitivity_summary.png` | 最终成功标记、最大抬升、最终平面距离 |
| `timing_traces.png` | 实际夹爪宽度、碗抬升、碗盘距离 |
| `eef_timing_traces.png` | 世界 x/y/z 的末端位置曲线 |
| `gripper_timing.png` | 夹爪指令与实际宽度的时序对照 |
| `per_step_metrics.csv` | 逐控制周期的可分析数值 |
| 每条件 `.npz` | 实际动作、完整状态与物体轨迹 |

视频规则在结果出现前确定：基准、最小失败夹爪延迟（若都成功则为 200ms）以及 hold_4。视频通过重新执行相同控制条件生成，检查渲染与非渲染状态差小于 1e-7；这项重复检查不增加独立示范数量。

另生成 `baseline_vs_perturbed.mp4`：左侧基准；右侧优先选择上述视频中失败的条件，若均成功则显示 200ms 夹爪延迟。完整结果仍列出所有条件，不只展示视频对应的条件。若没有失败，会明确写“未观察到失败”，不把成功片段标成失败。

所有单条件视频包含 137 帧（包括最后状态），20fps、6.85 秒。对照视频同样保留全部帧。

## 在现有服务器复跑

```bash
cd /root/autodl-tmp/wam_glance_project
bash day1/run_control_sensitivity_cpu.sh
```

脚本按顺序执行；每个回合独立子进程，结束后释放原生仿真内存。当前环境不增加依赖，不加载 Torch 或策略。`--resume` 可跳过已有数值回合，但仍会生成并核对选定的视频；如改变协议或输入数据，应使用新输出目录，避免复用旧结果。

输出位置：

```text
/root/autodl-tmp/wam_glance_project/results/control_sensitivity
/root/autodl-tmp/wam_glance_project/wam_control_sensitivity_full.zip
/root/autodl-tmp/wam_glance_project/wam_control_sensitivity_review.zip
```

完整包包含全部数组、曲线和视频；审阅包保留结果表、图表和视频。两个包均提供逐文件 SHA256。本地回传结果的目录为 `wam_day1/control_sensitivity_review/control_sensitivity`。

代码入口：`control_sensitivity_cpu.py` 定义动作时序和物理实验；`package_control_sensitivity.py` 生成附加曲线、结果表和并排视频；`test_control_sensitivity.py` 检查延迟冲刷、等时长和不误延迟机械臂的协议约束。

## 与后续模型实验的连接

这里建立的是一个可复用的控制链路检查，不能证明 WAM 的延迟鲁棒性。GPU 恢复后应分别记录模型推理耗时、动作块到达时刻、控制消费时刻和夹爪切换，再在闭环策略中研究延迟。保持 20Hz 消费动作块、降低重规划频率，与本实验的重复单条增量命令是两种实现。

如果这九个条件都成功，只能说明这条示范在已测范围内未失败；需要更多已匹配示范或更大扰动才能研究边界。若追加扰动，应单独标为探索性扩展，保留这九个条件的原始结果。
