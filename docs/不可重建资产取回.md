# 不可重建资产取回说明

## 前提：这台容器不能被直接拉取

实测结果决定了取回方式，不要凭想当然：

| 项 | 实测 |
|---|---|
| sshd 端口 22 | **未监听** |
| 容器 IP | `172.17.0.9`（Docker 私有网段） |
| 公网入口 | 无 |

所以**新服务器无法直接 `rsync` 这台实例**，AutoDL 实例必须经过它自己的网关隧道访问。能连到它的只有你的本地机器。

出网是通的：`git push` 到 GitHub 从这台容器成功过。若想让资产立刻脱离本机，可从容器主动上传（见文末方案 B）。

## 资产

```
/root/autodl-tmp/wam_glance_project/irreproducible_assets.tar
```

| 项 | 值 |
|---|---|
| 大小 | 1192652800 字节（1.19 GB） |
| 文件数 | 138 |
| SHA256 | `a2a52d0ffffdd5956dc5afcc138f385df3c6314f79bf638c74d80c3fe6a91ef9` |

内容：`P_seed42` 与 `C_seed42` 的 `best.action.pt` 及元数据、120 个归档 `*_actions.npy`。有意排除 `last.action.pt`（只评估 best）与 `base_seed42`（HF 可下载）。包内已含 `irreproducible_SHA256.json`，逐文件期望哈希也归档在 [irreproducible_assets](../results/irreproducible_assets/irreproducible_SHA256.json)。

## 方案 A：从本地机器拉（推荐，不需要任何新凭据）

你平时用什么命令连这台 AutoDL，就沿用同一条。

```bash
# 1) 拉下来（1.19 GB，走 AutoDL 隧道，会比较慢）
rsync -avP --progress \
  -e "ssh -p <你平时的SSH端口>" \
  root@<你平时的AutoDL连接地址>:/root/autodl-tmp/wam_glance_project/irreproducible_assets.tar \
  ./irreproducible_assets.tar

# 2) 校验整包
sha256sum irreproducible_assets.tar
# 必须等于 a2a52d0ffffdd5956dc5afcc138f385df3c6314f79bf638c74d80c3fe6a91ef9

# 3) 再推到新服务器
rsync -avP --progress ./irreproducible_assets.tar <新服务器>:/root/autodl-tmp/wam_glance_project/

# 4) 在新服务器上解包并逐文件校验
tar -xf irreproducible_assets.tar        # 必须保持 results/ 相对路径
/root/autodl-tmp/wam_glance_project/GlanceWAM/.venv/bin/python \
  /root/autodl-tmp/wam_glance_project/glance_wam_light/day1/package_irreproducible_assets.py \
  --root . --out irreproducible_assets.tar --verify
```

第 4 步退出码 0 表示 138 个文件全部一致。任何非 0 都不要继续，先重传。

## 方案 B：从容器主动上传（资产立刻脱离本机）

需要一个有 `repo` 权限的 Personal Access Token。Release 附件单文件上限 2 GB，无需 Git LFS，1.19 GB 可以直接放。

```bash
cd /root/autodl-tmp/wam_glance_project
REPO=Wzj479/glance_wam_light
TAG=irreproducible-assets
REL=$(curl -sS -X POST -H "Authorization: Bearer $TOKEN" \
  -H "Accept: application/vnd.github+json" \
  https://api.github.com/repos/$REPO/releases -d "{\"tag_name\":\"$TAG\",\"name\":\"Irreproducible assets\",\"body\":\"138 files that no public source can rebuild. See docs/不可重建资产取回.md\",\"draft\":true}" \
  | /root/autodl-tmp/wam_glance_project/GlanceWAM/.venv/bin/python -c "import json,sys;print(json.load(sys.stdin)['upload_url'])")
curl -sS -X POST -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/octet-stream" \
  --data-binary @irreproducible_assets.tar "$REL?name=irreproducible_assets.tar"
```

新服务器随后直接取：

```bash
curl -L -o irreproducible_assets.tar \
  https://github.com/Wzj479/glance_wam_light/releases/download/irreproducible-assets/irreproducible_assets.tar
sha256sum irreproducible_assets.tar   # 期望 a2a52d0ffffdd5956dc5afcc138f385df3c6314f79bf638c74d80c3fe6a91ef9
```

## 为什么这两个必须保住

它们无法从任何公开来源重建：检查点是本项目采样训练的产物，动作数组只能由该检查点在归档协议下重跑产生。发布仓库里没有任何文件能替代——862 条清单中 `.pt` 数量为 0，已发布的 21 个动作数组全属于无关的pilot 运行。

归档动作数组尤其关键：状态 33 诊断第 0 步的门禁就是「复现归档的 300 步动作」。缺了它，那轮诊断作废。`results.json` 里没有 `action_sha256` 字段，因此也没有任何可替代的校验凭据。

## 顺序建议

先取包（不依赖环境搭建，几分钟），再考虑环境迁移。在 tar 落到另一台机器之前，这台实例仍是单点。
