# 第二任务迁移检验：task 1 = put_the_bowl_on_the_stove

## 目的

检验 task 08 上发现的「过早松爪」机理与在线夹爪规则，能否迁移到第二个抓取放置任务。

## 方法

- 任务：LIBERO-Goal **task 1**（`put_the_bowl_on_the_stove`），抓取物仍是 `akita_black_bowl_1`，放置目标是固定家具 `flat_stove_1`（据 bddl 与 `obj_body_id` 确认；目标无 object 包装，故 driver 新增 `--grasp-body/--target-body` 支持）。
- 初态：init 0–9（协议 `protocols/protocol_task1_{a,b}.json`），base 权重，color_strong。
- 官方成功由 LIBERO goal 检查 `(On akita_black_bowl_1 flat_stove_1_cook_region)` 给出（env `done`）。
- 在线规则同 task 08：首次闭爪后，累计闭爪未满 `min_closed_steps` 就抑制张爪。
- **每个臂重复 5 次**（同初态、同协议、同 seed，独立服务器进程与仿真回合；GPU 非确定性使回合产生不同动作轨迹），按 task 08 的翻转率口径统计，不采信单次读数。

## 结果（5 次重复）

| 臂 | 单次 | 5 次重复合计 |
|---|---|---|
| base | 2/10 | **10/50（=2.0/10）** |
| 规则 `min_closed_steps=50` | 6/10（单次偏乐观） | **27/50（=5.4/10）** |

逐回合成功次数（x/5）：

| 回合 | base | 规则 N=50 | 判定 |
|---|---|---|---|
| ep0 / ep4 | 5/5 / 5/5 | 5/5 / 5/5 | 基线成功，**零副作用** |
| ep6 / ep7 / ep9 | 0/5 | **5/5 / 5/5 / 5/5** | **稳定救回** |
| ep2 | 0/5 | 1/5 | 翻转，**不可靠** |
| ep3 | 0/5 | 1/5 | 翻转，**不可靠** |
| ep1 / ep5 / ep8 | 0/5 | 0/5 / 0/5 / 0/5 | **未救回** |

> **单次读数 6/10 高估了**：ep2 的那次成功只是 1/5 的翻转。重复后真实增量是 **2.0/10 → 5.4/10**，且**集中在 ep6/7/9 三个稳定救回**；ep2/ep3 是不可靠翻转，ep1/ep5/ep8 修不了。base 侧 10/50 完全稳定（两个成功回合 5/5、其余 0/5），说明 task 1 的 base 失败是稳定的、可逐回合归因。

## 机理迁移：成立

按「首次闭爪后连续闭合帧数」看（base）：

- 成功 ep0/ep4：首次闭爪 ~36–37，**连续闭合 56 步**（接触 47/56 帧）；
- 失败 8 个：首次闭爪 36–44（**时机与成功相近**），但**只连续闭合 2–14 步**就张开。

与 task 08 同构：不是「闭太早」，而是**闭合后没持住**（task 08 成功持 32–34、失败 11–20；这里成功持 56、失败 2–14）。

## 规则迁移：部分成立，稳定救回 3 个

- **稳定救回 ep6/ep7/ep9（各 5/5）**，对两个基线成功回合**零覆盖、零副作用**。
- ep2/ep3 只在 5 次里各成功 1 次（翻转），不能算修复。
- **未救回的 ep1/ep5/ep8** 在 N=50 下已经**强制闭爪 50–53 步、接触 40+ 帧**（确实抓住并持住了），仍然失败——失败发生在更下游（放置/滑移），不是松爪时机。与 task 08 的 **state 35** 同类。

## 结论

1. **「过早松爪」机理跨任务、跨 checkpoint 成立**：task 1 上仍是主失败模式（成功回合持 56–58 步、失败 1–20 步），且 base/C/P 三者同构；base 失败稳定可逐回合归因。
2. **在线规则可迁移但更弱**：base 真实增量 **2.0/10 → 5.4/10**（5 次重复），稳定救回 3/8（ep6/7/9），零副作用；C 2→5、P 1→6，未救回集合一致（ep1/ep5/ep8）。单次的 6/10 是翻转造成的乐观读数。
3. **残留是另一类失败，且已定性**：**运输打滑**。强制持住后，slip ≤15mm 几乎完全决定成败（base 5 次重复准确率 0.98，C/P 完全分离）；ep1/ep5/ep8 是「夹得不稳、搬运就滑到 20–57mm」，不是松爪时机问题，也不是放置几何问题。与 task 08 的 state 35 同属规则覆盖不到的类。

## 跨 checkpoint 复核（base / C / P）

同 task 1、同 10 个初态、color_strong：

| checkpoint | 无规则 | 规则 N=50 |
|---|---|---|
| base | 2/10（5 次重复 10/50） | 5.4/10（27/50，5 次重复） |
| C | 2/10 | 5/10（单次） |
| P | 1/10 | 6/10（单次） |

「过早松爪」机理**与 checkpoint 无关**：base/C/P 的成功回合都是首闭后连续闭合 **56–58 步**，失败回合只闭 **1–20 步**（多数 2–13）；三者首闭时机都在 36–44。规则对三个 checkpoint 都有效，且**未救回集合一致（ep1/ep5/ep8）**；ep2/ep3 在翻转边缘（ep3 被 P 救回、base/C 未救回）。与 task 08 的「规则与 checkpoint 无关」一致。

## 第二类失败：运输打滑

用 `relative_slip_mm`（碗相对末端坐标系的位移）作判据，在**规则强制持住**的条件下：

| 条件 | slip ≤ 15mm 预测成功的准确率 | 成功回合 slip | 失败回合 slip |
|---|---|---|---|
| base 规则 N=50（5 次重复，50 回合） | **0.98**（真阳27/假阳0/假阴1/真阴22） | ≤14mm | 20–57mm |
| C 规则 N=50 | 10/10 分离 | 11mm | 31–54mm |
| P 规则 N=50 | 10/10 分离 | 11–14mm | 32–53mm |

即：**一旦强制持住，成不成几乎完全由运输中的相对打滑决定**（成功 ≤14mm，残留失败 32–57mm）。这解释了为什么「持更久」救不了 ep1/ep5/ep8——它们确实抓住并持住了，但夹得不稳，一搬运碗就在夹爪里滑到 20–57mm，最终没送到灶台。

注意两点：
- **无规则的 base 失败回合 slip 只有 ~11mm**，因为它们提前松爪、根本没进入搬运，所以这条判据只在「已持住」的条件下成立，不能当通用预测器。
- `xy_distance_m` / `above_plate` 这两列对 task 1 不可用于判成败（目标 `flat_stove_1` 的 body 原点与 `flat_stove_1_cook_region` 不重合，成功的 ep6/7/9 的 bowl-灶体 XY 也有 360–400mm）；官方成功仍以 env `done` 为准。
