# 第二任务迁移检验：task 1 = put_the_bowl_on_the_stove

## 目的

检验 task 08 上发现的「过早松爪」机理与在线夹爪规则，能否迁移到第二个抓取放置任务。

## 方法

- 任务：LIBERO-Goal **task 1**（`put_the_bowl_on_the_stove`），抓取物仍是 `akita_black_bowl_1`，放置目标是固定家具 `flat_stove_1`（据 bddl 与 `obj_body_id` 确认；目标无 object 包装，故 driver 新增 `--grasp-body/--target-body` 支持）。
- 初态：init 0–9（协议 `protocols/protocol_task1_{a,b}.json`），base 权重，color_strong。
- 官方成功由 LIBERO goal 检查 `(On akita_black_bowl_1 flat_stove_1_cook_region)` 给出（env `done`）。
- 在线规则同 task 08：首次闭爪后，累计闭爪未满 `min_closed_steps` 就抑制张爪。

## 结果

| 臂 | 成功 | 说明 |
|---|---|---|
| base | **2/10** | 只有 ep0、ep4 成功 |
| 规则 min_closed_steps=30 | **5/10** | 新增 ep6/7/9；ep0/ep4 仍成功、0 次覆盖，无副作用 |
| 规则 min_closed_steps=50 | **6/10** | 再新增 ep2；ep0/ep4 仍成功、0 次覆盖 |

## 机理迁移：成立

按「首次闭爪后连续闭合帧数」看（base）：

- 成功 ep0/ep4：首次闭爪 ~36–37，**连续闭合 56 步**（接触 47/56 帧）；
- 失败 8 个：首次闭爪 36–44（**时机与成功相近**），但**只连续闭合 2–14 步**就张开。

即与 task 08 同构：不是「闭太早」，而是**闭合后没持住**（过早松爪）。task 08 是成功持 32–34、失败 11–20；这里是成功持 56、失败 2–14。

## 规则迁移：部分成立，且窄而准

- 阈值 30 救回 3/8，阈值 50 救回 4/8；对两个基线成功回合**零覆盖、零副作用**。
- **显著弱于 task 08**（那里 19/20、28/34/42 共 45/45）。原因不是机理不对，而是**存在第二类失败**：
  未救回的 ep1/ep3/ep5/ep8 在 N=50 下已经**强制闭爪 50–53 步、接触 40–44 帧**（确实抓住并持住了），仍然失败——失败发生在更下游（放置/滑移），不是松爪时机。
  这与 task 08 的 state 35 同类（放置阶段失败、规则 0/5）。

## 结论

1. **「过早松爪」机理跨任务迁移成立**：第二个抓取放置任务上仍是主失败模式。
2. **在线规则可迁移但更弱**：base 2/10 → 6/10，且零副作用；优势仍是「窄而准」，只修松爪时机这一类。
3. **残留失败是另一类**：抓住并持住仍失败，提示放置/滑移问题；规则的边界因此更清楚。
